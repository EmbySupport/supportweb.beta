    GPU Setup on Linux

    On Linux, Nvidia hardware needs drivers installed separately, and Rockchip SoCs need a vendor kernel and device permissions. For Intel and AMD, everything required ships with Emby Server.

    What each vendor's hardware can actually do is described under Hardware Acceleration.

    Nvidia

    Note

    A sufficient driver version alone does not mean that all components needed for video encoding and decoding are installed.

    On older Linux distribution releases, install the drivers from Nvidia Driver Downloads, following Nvidia's installation instructions, rather than using the driver packages supplied by the distribution. Older distributions frequently package only a subset of what Nvidia provides, omitting components needed for video encoding and decoding.

    On the latest Linux distribution releases available as of 2026, the Nvidia drivers supplied through the distribution's package manager can be used, provided the required video encoding and decoding components are included. This exception does not apply to older distribution releases.

    The minimum required version on Linux is 520.56.06.

    Nvidia works headless - no monitor has to be attached.

    Intel

    No setup is required. The drivers needed for Intel hardware acceleration are included with Emby Server.

    AMD

    No setup is required. The drivers needed for AMD hardware acceleration are included with Emby Server.

    Rockchip

    Rockchip hardware acceleration requires the Rockchip BSP (vendor) kernel, 5.10 or 6.1 LTS. All of the following steps need root permission.

    1. Check that dma_heap, dri, mpp_service and rga exist in /dev:

      ls -l /dev | grep -E "mpp|rga|dri|dma_heap"

      If they don't, upgrade the BSP kernel to 5.10 LTS or newer.

    2. Grant access to the device files by creating /etc/udev/rules.d/99-rk-device-permissions.rules with the following content, then restart the machine:

      KERNEL=="mpp_service", MODE="0660", GROUP="video"
KERNEL=="rga", MODE="0660", GROUP="video"
KERNEL=="system", MODE="0666", GROUP="video"
KERNEL=="system-dma32", MODE="0666", GROUP="video"
KERNEL=="system-uncached", MODE="0666", GROUP="video"
KERNEL=="system-uncached-dma32", MODE="0666", GROUP="video" RUN+="/usr/bin/chmod a+rw /dev/dma_heap"

    3. Add the emby user to the render and video groups (on some distributions the group is input), then restart Emby Server:

      sudo usermod -aG render emby
sudo usermod -aG video emby
sudo systemctl restart emby-server

    4. For HDR tone mapping on the RK3588/RK3588S only: install the Arm Mali OpenCL runtime (libmali). Its version has to match the kernel driver, otherwise OpenCL does not work:

      • 6.1 LTS kernel on Ubuntu-Rockchip or Armbian, and the legacy 5.10 LTS kernel: v1.9-1-2131373
      • 6.1 LTS kernel on other distributions made by board vendors: v1.9-1-55611b0

    Afterwards, the hardware detection result under Operations → Detection Logs shows whether the SoC was detected.

    To watch the hardware at work while a video transcodes, read the VPU and RGA load:

    sudo sh -c "echo 1000 > /proc/mpp_service/load_interval" && sudo watch -n 1 cat /proc/mpp_service/load
sudo watch -n 1 cat /sys/kernel/debug/rkrga/load

    VPU load can only be read reliably on BSP kernels from 6.1.84 onwards.
